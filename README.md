# AVIF + WebP on Upload

🇺🇸 English (you are here) · 🇧🇷 [Leia em Português](README.pt-BR.md)

A lightweight WordPress plugin that automatically converts uploaded images to **AVIF**, generates **WebP** mirrors for every size, and removes the original JPG/PNG files, so your media library takes up less disk space and your site loads faster.

> **Version:** 2.4 · **Requires WordPress:** 6.5+ · **Requires PHP:** 7.4+ · **License:** GPL-2.0-or-later

---

## Why use it

Images are usually the heaviest part of a web page. AVIF delivers the same visual quality as JPG and PNG in much smaller files, and WebP works as a fallback for browsers that do not support AVIF.

Real results from regular uploads (AVIF quality 60, WebP quality 75):

| Uploaded image | Original | Main AVIF | Main WebP |
|---|---|---|---|
| 2048 × 2048 photo (JPG) | 465 KB | 160 KB (-66%) | 199 KB (-57%) |
| 3840 × 2160 screenshot (JPG) | 447 KB | 32 KB (-93%) | 48 KB (-89%) |
| 2304 × 4096 phone photo (JPG) | 2.1 MB | 62 KB (-97%) | 80 KB (-96%) |

Savings vary with the image content. Screenshots and images with flat areas compress far more than detailed photos.

---

## What the plugin does

1. **Converts to AVIF** the main file and every thumbnail generated by WordPress, including the `-scaled` version of images larger than 2560 px.
2. **Generates WebP mirrors** for the main file and for each size, next to the AVIF files, with the same base name (`photo-300x200.avif` and `photo-300x200.webp`).
3. **Removes the originals** (JPG, PNG, WebP, and the `original_image` kept before `-scaled`), but only after validating that the main AVIF and every WebP exist and open as real images.
4. **Preserves orientation** of phone photos (EXIF) in the WebP mirrors.
5. **Leaves animated images alone** (animated WebP, animated AVIF and APNG). GIF and SVG also pass through untouched.
6. **Cleans up together**: when you delete a media item in WordPress, its WebP mirrors are removed from disk too.

### Safety of the process

- The main AVIF is written to a temporary file and only moved into place if it is valid.
- If any step fails, **the originals are kept** and the reason is written to the PHP `debug.log`.
- If the server has no AVIF support, the plugin does nothing.
- If the server has no WebP support, the plugin keeps going and simply skips the mirrors.

## Requirements

- WordPress **6.5 or newer** (AVIF support in core).
- PHP **7.4 or newer** (tested on PHP 8.4).
- A server whose image editor supports **AVIF**: Imagick with libheif/libavif, or GD with `imageavif()`.
- For the WebP mirrors, WebP support in the same editor.

To check support, go to **Tools > Site Health > Info > Media Handling**.

## Installation

1. Download the `avif-webp-on-upload.php` file from this repository.
2. Upload it to `wp-content/plugins/avif-webp-on-upload/` (or to `wp-content/mu-plugins/`).
3. Activate it under **Plugins** in the WordPress admin.

---

## Configuration

There is no settings screen. The values live in the plugin file itself:

| Setting | Default | Where to change it |
|---|---|---|
| AVIF quality | 60 | `wp_editor_set_quality` filter and `set_quality( 60 )` |
| WebP quality | 75 | `wp_editor_set_quality` filter and `set_quality( 75 )` |

For screenshots with a lot of text, a higher AVIF quality (for example 70 to 80) avoids softened letter edges.

## Limitations and important warnings

**Read before using in production.**

- **Removing the originals is permanent.** Back up your `uploads` folder before activating the plugin. Once deleted, the original JPG/PNG cannot be recovered.
- **It only affects new uploads.** Media already in your library is not converted.
- **Image editing in the admin** (crop, rotate, restore original) is not covered. Because the original is removed, the restore option does not work.
- **Thumbnail regeneration plugins** (such as Regenerate Thumbnails) will recreate sizes from the already compressed AVIF, with quality loss on each generation.
- **The WebP mirrors are not registered in WordPress.** They sit on disk, but the plugin does not change the HTML or the image URLs. Delivering the WebP is the server's job (see below).
- **Old URLs** pointing to `.jpg` or `.png` in already published posts keep pointing to files that no longer exist for new uploads.

## Serving WebP to browsers without AVIF (optional)

WordPress will use the `.avif` as the main file, and almost every modern browser supports it. If you want to serve the `.webp` to the small group that does not, configure your server.

Example for **nginx** (adapt it and test in your own environment before using):

```nginx
map $http_accept $avif_ok {
    default          0;
    "~*image/avif"   1;
}

location ~* ^(?<base>.+)\.avif$ {
    add_header Vary Accept;
    if ($avif_ok = 0) {
        try_files $base.webp $uri =404;
    }
}
```

On Apache, equivalent rules using `mod_rewrite` and the `Accept` header work the same way.

## How to test

1. Upload a JPG through the media library.
2. In the `uploads` folder, confirm there are `.avif` and `.webp` pairs for the main file and every size, and that the JPG no longer exists.
3. Compare sizes: the `.avif` should be smaller than the `.webp`.
4. Delete the media item and confirm every file disappears from disk.

If an original stays on disk, look in `debug.log` for `[AVIF+WEBP] Originais mantidos por seguranca`.
